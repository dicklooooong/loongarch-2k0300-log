# 专题：走马观碑卡牌分类（阶段总结 10-21 ~ 10-23）

> 三天时间，从"摄像头打不开"做到"**9 种卡牌分类 96.6%**"。
> 这篇是阶段总结：把散在三天日报里的结论收拢成可复用的地图。
> 过程细节看 [2026-10-21.md](../../logs/2026/10/2026-10-21.md)、[2026-10-22.md](../../logs/2026/10/2026-10-22.md)、[2026-10-23.md](../../logs/2026/10/2026-10-23.md)。

## 一、为什么需要它（动机与用途）

- **触发场景**：老师的任务"走马观碑"——车经过时识别卡牌属于哪一类。
- **我们做的那一版**：不用车，**摄像头对着卡牌拍，判断它是三大类（武器/物资/载具）里的哪一类**。
- **掌握后能做什么**：板子独立完成"摄像头取图 → 预处理 → 神经网络推理 → 输出类别"，全程 ~28ms。
- **值不值得投入**：值得。这套链路（UVC 取流 + ncnn 推理 + 数据集训练 + 板端部署）可以复用到任何图像分类任务。

## 四、核心概念

### 概念 1：验证集必须按"连拍组"划分

- **一句话**：同一姿态连拍的 3 张图必须整体进训练集或整体进验证集。
- **为什么**：连拍 3 张几乎一模一样。随机划分会让"训练集里的图"和"验证集里的图"重复，val_acc 虚高 20~30 个点。
- **证据**：随机划分时报 95.45%，按组划分后只有 66.7%（相差 29 个点）。
- **最小验证**：训练日志里 `Train/Val/Test` 三个数字的分布，再看验证集里有没有和训练集同姿态的图。

### 概念 2：数据量和模型容量必须同步增长

- **一句话**：只加数据不加容量、或只加容量不加数据，都不会变好。
- **证据**（同一批 90 张留出图）：

| 版本 | 训练数据 | 参数 | 准确率 |
| --- | --- | --- | --- |
| v9 | 426 张 | 10.7K | 73.3% |
| v14 | 603 张（只加数据） | 10.7K | 71.1% ↓ |
| v8 | 234 张（只加容量） | 10.7K→ | 53.7% ↓ |
| **v15** | **603 张 + 22.3K** | | **81.1%** ↑ |
| v16 | 603 张 + 37.9K | | 81.1%（耗时 +54%） |

- **结论**：22.3K 是这个数据量下的甜点。

### 概念 3：小类聚合大类（层次分类）在小数据下没优势

- **一句话**：每类样本 < 100 张时，先分小类再聚合，一定比直接分大类差。
- **证据**：

| 场景 | 直接大类 | 小类→聚合 |
| --- | --- | --- |
| 公开数据（每类 ~40 张） | 88.3% | 六分类 80.0% |
| 实拍数据（每类 ~45 张） | 73.3% | 九分类 50.0% |

- **什么时候才值得**：每类 ≥ 150 张。

### 概念 4：置信度可以当"不确定"的信号

- 预测正确时平均置信度 **0.706**，错误时 **0.538**。
- 可以加一条：`conf < 0.5` 输出"不确定"，现场知道哪张没把握。

### 概念 5：模型看到的不只是物体，还有构图

- 所有卡牌都是"白纸 + 手 + 同一张桌子"，背景恒定 → 模型只能用轮廓。
- 于是"白纸上的黑色细长物体"（手电筒/警棍/步枪）互相混。
- **对策**：换背景、变距离、局部遮挡，逼模型看物体本身。

## 五、实践记录（按时间倒序追加）

### 2026-10-23 数据翻倍 + 容量翻倍 → 96.6%

- 数据：522 → 744 → 933 张（补消防车、手电筒、手枪、警棍、步枪）
- 五版对比：v14 71.1% / v15 81.1% / v16 81.1% / v17 85.6%（90 张集）/ v18 84.4%
- **换 177 张验证集后 v17 = 96.6%**，手电筒 100%
- 结论：数据+容量同步；验证集要 ≥ 20 张/卡种
- 证据：[assets/2026-10-23-model-capacity-eval.txt](../../assets/2026-10-23-model-capacity-eval.txt)

### 2026-10-22 实拍数据闭环 → 73.3%

- 公开数据三轮对比：作者 85.0% / r2 81.7% / v3（劣化增强）88.3%
- 六分类聚合 80.0%（低于三分类）
- 卡牌到了：写 `capture`/`shots`/`stream` 三个采集模式，采 492 张
- v7 66.7% → v9 73.3%
- 修掉两个 bug：采集图全黑（曝光没预热）、绿字烧进图片（先画字后存图）
- 证据：[assets/2026-10-22-card-classification-eval.txt](../../assets/2026-10-22-card-classification-eval.txt)

## 六、踩坑清单（排错先看这里）

| 现象（原文关键词） | 原因 | 解决 |
| --- | --- | --- |
| `/proc/devices` 里没有 `81 video4linux` | 原厂内核没编 V4L2 | 刷 202506 版内核 |
| 刷完内核 `reboot` 后整个网段不通 | 板子 bootloader 重启异常 | **只能断电重启**，别用 `reboot` |
| 采集图全黑，亮度 3.7/255 | 手动曝光 300 太暗 + 自动曝光没预热 | `set_auto_exposure(3)` + 30 帧预热，亮度到 133 |
| 保存的图左上角有绿色 `SHOT 1/3` | 先画提示字、后存图，用的是同一份 frame | 改成**先存图、后画字**（画字只影响预览） |
| 画面彩色雪花 / 颜色反了 | SCC8660 里 RGB565 字节序被换过一次，viewer 又换一次 | viewer 端默认再对调一次（`--swap`） |
| 训练 val_acc 95%，实拍只有 66.7% | 随机划分导致同姿态数据泄漏 | 按连拍组划分验证集 |
| 板子上 `ex.extract(0, out)` 输出 100 维 | 老版 ncnn 输出 blob 不是索引 0 | 用 `ex.extract(net.output_names()[0], out)` |
| 板子上 `net.input_names()[i].c_str()` 编译错 | 老版返回 `vector<const char*>` | 直接用 `net.input_names()[i]` |
| scp 报 `Text file busy` | 板上程序正在运行，Linux 不允许覆盖 | 先 `pkill -f ncnn_cls` 再传 |
| 采集中途重启，编号从 0001 覆盖旧图 | `seq` 每次从 0 开始 | 加 `max_existing_index()`，从已有最大编号+1 继续 |
| 训练日志 `Classes: ['a_gun',...]` 但准确率低 | 小类样本太少 | 每类 < 100 张时直接分大类 |

## 八、复述检验（能讲清才算学会）

> 假装配一张卡牌给同学讲，不查资料说 5 句话：

1. **它干什么**：摄像头拍卡牌，板子判断是武器、物资还是载具。
2. **数据怎么流**：UVC 出 MJPG → OpenCV 解成 BGR → 缩放 96×96、转 RGB、减均值除方差 → ncnn 前向 → softmax → 取最大。
3. **模型怎么来**：卡牌拍 160×120 图 → 按卡种存文件夹 → 训练小 CNN（22K 参数）→ 导 ONNX → pnnx 转 ncnn → scp 到板子。
4. **最大的坑**：验证集划分。同姿态连拍必须整组留出，否则准确率虚高 20 多点。
5. **现在到哪**：9 种卡 96.6%，载具类偏弱（88%），真实装车还没试。
