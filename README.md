# 龙芯 2K0300（久久派）学习日志

在龙芯 2K0300（久久派）平台上做嵌入式开发的长期记录仓库。用模板降低记录成本，用固定目录让历史可检索，用 Git 提交历史留下成长轨迹。

- 记录粒度：**每日**（今天动了什么）→ **每周**（复盘与调整）→ **专题**（某个子系统的沉淀）
- 嵌入式开发的日志重点不是"学了什么概念"，而是**现象、复现步骤、结论**——半年后回到同一个坑，能靠当时写的东西直接解决
- 一切以 Markdown 纯文本保存，不依赖任何软件；GitHub 上自动获得在线浏览与全文搜索

> 本仓库对应的远程地址：<https://github.com/dicklooooong/loongarch-2k0300-log>
> 状态：已推送并与远程一致（最新提交 `5554d49`）。日常只需 `git add` → `git commit` → `git push`。

## 三、命名规范

| 类型 | 路径 | 命名 | 示例 |
| --- | --- | --- | --- |
| 每日 | `logs/年/月/` | `YYYY-MM-DD.md` | `logs/2026/10/2026-10-16.md` |
| 每周 | `reviews/年/` | `YYYY-Www.md`（ISO 周） | `reviews/2026/2026-W42.md` |
| 专题 | `topics/` | `kebab-case.md` | `topics/boot-flow.md` |
| 附件 | `assets/` | `日期-主题.后缀` | `assets/2026-10-16-uart-boot-log.txt` |

> 用 `YYYY-MM-DD` 而非「10月16日」：文件按名称排序就是时间排序，跨年也不会乱。
> 串口日志、波形截图一律进 `assets/`，**日志正文里贴关键片段 + 链接到附件**，不要把几百行日志糊进 Markdown。

### 一天的边界：凌晨 6 点

**凌晨 6:00 之前写的内容，算作前一天。**

熬夜调车到凌晨 2 点，那次记录仍然归到「开始那天」的文件里，而不是第二天。
`daily.ps1` / `new-log.ps1` 已经内置这个规则：

```powershell
$today = Get-Date
if ($today.Hour -lt 6) { $today = $today.AddDays(-1) }
```

判断依据只看**当前钟点**，所以：

| 实际时间 | 归到哪一天 |
| --- | --- |
| 10-21 22:00 | `2026-10-21.md` |
| 10-22 00:30 | `2026-10-21.md` ← 凌晨 6 点前 |
| 10-22 05:59 | `2026-10-21.md` |
| 10-22 06:00 | `2026-10-22.md` |

要写到别的日期（补记），显式传 `-Date`：

```powershell
.\new-log.ps1 -Date 2026-10-19
```


## 四、标签体系（写在日志末尾）

保持 **5～8 个**主轴标签。2K0300 开发建议用这几类：

- 阶段：`#环境搭建` `#工具链` `#交叉编译` `#启动流程` `#内核` `#驱动` `#应用`
- 外设：`#串口` `#GPIO` `#网口` `#SPI` `#I2C` `#存储`
- 形态：`#踩坑` `#调试` `#读手册` `#动手实践` `#复盘`
- 状态：`#已解决` `#待验证` `#有疑问`

## 五、日常使用流程

> **最短流程：只双击一个文件 —— [`每天记录.cmd`](每天记录.cmd)**
>
> 它会按当天日期建好（或打开）日志 → 你写完**保存并关闭编辑器** → 它自动提交并推送到 GitHub。
> 全程只需要一次双击和一次保存关闭。
>
> 下面是想记细一点时的完整说明。

**每天 5 分钟（收尾时做，别攒到周末）**

1. 用 `new-log.cmd` 生成当天文件
2. 只填四格：今天做了什么 → **现象 vs 预期** → 卡点与疑问 → 明天第一步
3. 有命令/配置/串口输出就贴进「片段」区，并写清**在什么版本下执行**
4. 结论要能复现：写"怎么验证的"，不只写"是……导致的"

**每周 20 分钟**

1. 复制 `templates/weekly.md` 到 `reviews/当年/YYYY-Www.md`
2. 翻一遍本周日志，合并重复，提炼规律（同一个坑出现两次，就该写进专题）
3. 把值得长期保留的内容**搬家**到 `topics/`

**随时**

- 某个子系统累计到 3 篇以上日志，就在 `topics/` 建专题文件，并登记到 `topics/README.md`

## 六、一键创建今天日志

> 日常请用 [`每天记录.cmd`](每天记录.cmd)（见上一节，创建 + 编辑 + 发布一步到位）。
> 本节两个脚本用于**补写某一天**或**只发布不编辑**。

仓库自带脚本 [`new-log.ps1`](new-log.ps1)：按当天日期自动建好目录、套用模板、填好日期与星期，并用编辑器打开（已有则直接打开，不覆盖）。

**最简单的方式**：双击 [`new-log.cmd`](new-log.cmd)，它内部已加 `-ExecutionPolicy Bypass`，不受脚本执行策略限制。

```powershell
cd loongarch-2k0300-log
.\new-log.cmd                    # 创建今天的日志
.\new-log.cmd -Date 2026-10-01   # 补写某一天
```

直接调用 PowerShell 脚本也可以（若被提示"禁止运行脚本"，执行一次
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`，仅对当前用户生效）：

```powershell
.\new-log.ps1 -Date 2026-10-01
```

## 七、提交到 GitHub

**首次推送已完成**：本地仓库已初始化、远程 `origin` 已关联、首个提交已推送。

**一键发布（推荐）**：双击 [`publish.cmd`](publish.cmd)，或运行 `.\publish.cmd "串口无输出排查"`。
它会自动 `git add -A` → 用 `log(daily): 日期 主题` 提交 → `git push`；没有改动时只提示、不产生空提交。
中文提交信息以 UTF-8 写入临时文件再提交，不会乱码，也不会弹出编辑器。

[`init-and-push.cmd`](init-and-push.cmd) 可**重复运行**：它会按需 `git init`、提交当前改动、补上远程地址并推送。换新机器时也用它。

**手动三步**（一键脚本做的事）：

```bash
git add .
git commit -m "log(daily): 2026-10-16 串口无输出排查"
git push
```

**提交信息约定**（方便日后 `git log` 检索）：

```
log(daily):   2026-10-16 今天主题
log(weekly):  2026-W42 周复盘
log(topic):   新增专题 boot-flow
assets:       补充串口启动日志
docs:         修改模板 / 说明
fix:          修正已有记录中的错误结论
```

> 详细步骤与常见报错（认证失败、非快进、中文乱码等）见 [`GITHUB-SETUP.md`](GITHUB-SETUP.md)。

## 八、三条原则

1. **写不完也要写**：3 行也比空白强，连续性比完整度重要
2. **记录"为什么"**：结论会过时，当时的判断依据和验证方式不会
3. **现象必须写清**：报错原文、串口输出、工具链版本——这三样缺一个，半年后这条记录就废了
