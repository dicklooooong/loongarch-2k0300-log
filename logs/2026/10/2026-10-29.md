## 五、关键收获（3 条）

1. **收获**：回传就是"板子当客户端"的 5 步——`init` 连电脑 → 换收发函数指针 → 登记缓冲/类型/尺寸 → 每帧填 RGB565 → `camera_send()`。｜为什么重要：协议和逐飞库解耦了，换成自己写 socket 也是同样 5 步，以后换板子不用重学。
2. **收获**：逐飞库的接口都是**薄封装**，遇到"库到底做了什么"直接看 `.cpp`，别信注释。`get_gray_image_ptr` 就是 `cvtColor`，`get_frame_mjpg` 就是浅拷贝——两个都和名字/注释给人的印象不一样。｜为什么重要：今天两次判断失误（以为有灰度/二值函数、以为返回副本）都是因为没先看实现。
3. **收获**：重构的顺序是**先跑通、再拆文件**；删代码前先问一句"它是不是还没被调用的脚手架"。｜为什么重要：今晚删过头重写了一遍 `main`，多花了将近一小时，功能没有增加。

### ③ `code/stream.cpp` 核心

```cpp
static zf_driver_tcp_client g_tcp_dev;
static uint16_t g_stream_img[UVC_HEIGHT][UVC_WIDTH];
static bool     g_ready = false;

bool stream_init(const char *ip, int port)
{
    if (g_tcp_dev.init(ip, (uint16)port) != 0) return false;
    seekfree_assistant_interface_init(send_wrap, recv_wrap);
    seekfree_assistant_camera_information_config(
        SEEKFREE_ASSISTANT_SCC8660, g_stream_img[0], UVC_WIDTH, UVC_HEIGHT);
    g_ready = true;
    return true;
}

void stream_push(const cv::Mat &frame)
{
    if (!g_ready || frame.empty()) return;

    cv::Mat b565;
    if (frame.channels() == 1)
        cv::cvtColor(frame, b565, cv::COLOR_GRAY2BGR565);   // 灰度/二值
    else
        cv::cvtColor(frame, b565, cv::COLOR_BGR2BGR565);    // 彩色

    const uint16_t *s = (const uint16_t *)b565.data;
    for (int k = 0; k < UVC_WIDTH * UVC_HEIGHT; k++)
        g_stream_img[0][k] = (uint16_t)((s[k] >> 8) | (s[k] << 8));  // 大端

    seekfree_assistant_camera_send();
}
```

### ⑤ 接收端协议（viewer.py 的期待）

| 偏移 | 内容 |
| --- | --- |
| 0-1 | `0xAA 0x02` |
| 2 | bit7-5 类型（3=SCC8660/RGB565），bit4 无图，bit3-0 边线数 |
| 3 | 包头长度 = 8 |
| 4-7 | 宽、高（小端 u16） |
| 8… | `w*h` 个 RGB565，高字节在前 |

> `viewer.py` 默认按"发送端已交换字节"解（`<u2` 再 `byteswap()`），板端换一次正好对上。
> 但 `cam-viewer\test_sender.py` 发的是没交换的小端，所以拿它自测要加 `--no-swap`，否则颜色是错的。
